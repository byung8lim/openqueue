# ADR-0006: 관리자 인증 방식 (DEC-07)

- 상태: **승인(소유자 2026-11-14)** — 초기 비밀번호 방식 확정(§2-1). 내장 계정 MFA 여부는 미응답(§3, Phase 5 전 확인)
- 영향도 등급: I4 (인증 구조)

## 1. 결정 (소유자, 2026-11-14)

| 구분 | 인증 방식 |
|---|---|
| 시스템 기본 Admin (내장 계정) | **id / password** |
| 일반 관리자 | **Keycloak(OIDC) + MFA** |

해석: 설치 직후 IAM 연동 전에도 시스템을 설정할 수 있는 **내장 관리자 계정 1개**를 제공하고,
운영 관리자는 기관 IAM(Keycloak/OIDC + MFA)으로 로그인한다. 두 방식 모두 같은 RBAC 역할 체계를 사용한다.

## 2. 내장 계정 안전장치 (제안)

기본 계정은 공격자가 가장 먼저 시도하는 대상이므로 다음을 필수로 제안한다.

1. **고정 기본 비밀번호 없음 (소유자 결정)**: 최초 부트업 시 임의 비밀번호를 생성해 **`initpassword.txt`에 저장**하고,
   최초 로그인 시 **비밀번호 변경 프로세스**를 반드시 거치게 한다. 세부 규칙(제안):
   - 생성 조건: 관리자 계정이 하나도 없을 때만 생성. 이미 있으면 파일을 만들지 않는다.
   - 파일 위치: 설정 키 `openqueue.admin.init-password-file`(기본 `<데이터 디렉터리>/initpassword.txt`). 소유자 = 서비스 계정, 권한 **0600**.
   - 내용: 암호학적 난수 24자 이상. 로그·stdout에는 **파일 경로만** 기록하고 비밀번호는 기록하지 않는다.
   - 비밀번호 변경 완료 시 파일을 삭제한다(삭제 실패 시 경고 로그 + 관리 화면 경고). 변경 전까지는 비밀번호 변경 화면 외 모든 관리 기능을 차단한다.
   - 파일이 외부로 노출될 위험 때문에 초기 비밀번호의 유효기간을 둔다(제안 24시간, 경과 시 재생성 절차 필요).
2. 비밀번호 저장: **Argon2id** 해시(실패 시 bcrypt). 원문·가역 암호화 저장 금지.
3. 비밀번호 정책: 최소 12자, 이전 비밀번호 재사용 금지.
4. 로그인 실패 5회 시 일정 시간 잠금, 실패·성공 모두 감사 기록(ADM-003).
5. 접근 위치: 내부 관리망 Control API에서만 사용 가능(DMZ에 로그인 엔드포인트 없음).
6. OIDC 연동 후 **내장 계정 비활성화 설정**을 제공(비상용으로만 다시 켤 수 있음, 켜고 끈 이력 감사).
7. 세션: 짧은 유휴 만료, 비밀번호 변경 시 기존 세션 폐기.

## 3. 확인 필요

- 내장 계정에도 **MFA(TOTP)**를 요구할 것인가? (권장: 선택 가능, 운영 환경 기본 활성)
- 내장 계정은 1개로 제한하는가, 여러 개의 로컬 계정을 허용하는가? (권장: 1개)
